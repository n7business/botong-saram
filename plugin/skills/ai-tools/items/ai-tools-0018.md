# AI로 기획서·명세서를 쓰면 길어지기만 하고 예외 케이스(결제 중 앱 종료 시 처리 등)가 빠지므로, 사람이 먼저 구조와 예외를 잡고 AI에는 마무리 보정만 맡긴다.

👤 한 사람이 말함 · 요즘IT

코드베이스를 읽히고 하네스를 잡아도 AI가 쓴 기획서는 불필요한 텍스트가 붙고 표가 읽히지 않으며, 읽는 사람이 아니라 프로그램이 읽기 편한 구조가 나온다. 더 큰 문제는 손으로 쓸 때 파트 내부 검수에서 잡히던 예외 케이스를 AI가 놓친다는 점이다. 장비 강화 예시에서 AI는 재화 차감 시점에 앱이 종료됐을 때의 처리, 결과 확정, 재접속 시 안내를 빠뜨렸다. 이를 고치려고 지침과 프롬프트를 다듬으면 작업량이 직접 쓰던 때와 비슷해진다. 따라서 사람이 문서를 직접 고친 뒤 오탈자·시인성 같은 후보정만 AI에 시키는 것이 현실적이다. 저자는 결국 문서 대신 돌아가는 목업과 실코드를 연동해 공유하는 방식으로 닷새 작업을 사흘로 줄였다고 보고한다.
